Why is 8× B60 slower than a single H100?
  • PCIe all-reduce overhead: tp=8 requires 8-way all-reduce per decode step via PCIe 5 (64 GB/s per direction). The H100’s HBM3 serves all weights locally at 3,350 GB/s with zero communication latency.
  • enforce-eager constraint: XPU support in vLLM requires --enforce-eager, disabling CUDA graph capture. CUDA graphs eliminate per-step kernel launch overhead (~2–4 ms), reducing each decode step by ~30–50% on NVIDIA.
  • GDDR6 vs HBM3: 456 GB/s per B60 vs 3,350 GB/s per H100 — a 7.4× bandwidth gap per GPU card.
Why use 8× B60 then?
  • Cost: 8× B60 ≈ $4,000 GPU cost. A single H100 SXM ≈ $25,000–35,000. Two H100s for 160 GB ≈ $50,000–70,000.
  • VRAM budget: 192 GB enables 131K-token context at concurrent scale. No NVIDIA single-GPU option provides 192 GB under $12,000.
  • Heterogeneous staging: The Xeon CPU classification stage adds 2.27× throughput at c=32 — an architectural gain unavailable on GPU-only stacks.

Conclusions

Retrieval Pipeline

  • FAISS HNSW delivers sub-20ms dense search at 12K vectors — well within interactive SLA
  • Cross-encoder reranking (437ms Torch/20) is the bottleneck but critical for quality
  • Full pipeline peaks at 91 q/s at C=4; ONNX backend option can push to ~19 q/s at C=1
  • Context packing saves 80–90% of tokens, directly reducing LLM cost per query

E2E Performance

  • Fast tier (IT Ops ~3.9s, Research ~4.8s): sub-5s for simple queries — interactive SLA
  • Medium tier (IT Ops ~16.5s, Research ~10.1s): multi-step reasoning in <20s
  • Deep tier (Research ~45s): comprehensive supervisor synthesis — faster than manual research by hours
  • LLM decode dominates (82–95% of E2E) — upgrade path is clear

Scenario Differences

  • IT Ops: bounded latency (no deep tier), human approval gate, entity-first pipeline — optimized for incident response SLAs
  • Deep Research: unbounded complexity available, supervisor loop, sub-agent parallelism potential — optimized for thoroughness over speed
  • Both share identical retrieval infrastructure — no duplication

Cost Efficiency

  • $0.000256/query at capacity — ~1,200× cheaper than GPT-4o API
  • Deep-tier Research queries cost $0.015 — negligible for enterprise strategic analysis
  • Monthly capacity: 1.65M queries at $423/month infra
  • Break-even at 68 IT incidents/month — any mid-size enterprise qualifies

Methodology

Component benchmarks run on Xeon 6 with 12,160-document IT Ops corpus (FAISS IndexHNSWFlat M=32, efSearch=64). E2E benchmarks invoke LangGraph graphs directly with live LLM inference (Llama-3.1-8B at tp=8 on 8× Arc Pro B60, Qwen2.5-3B on Xeon for classification + entity extraction). LLM times in the node breakdown tables are modelled estimates where E2E hasn't been run; real measurements available after bench_e2e.py runs. Cost model: $423/month total infrastructure.
